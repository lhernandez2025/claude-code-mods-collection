## plan-progress

Живые полосы прогресса над полем ввода Claude Code. Claude делит задачу на этапы и шаги, а полоса заполняется по ходу работы. Под полосой каждой задачи видны её субагенты.

![plan-progress: две задачи с агентами, вопрос, ошибка, план меняется по ходу, обе задачи готовы](media/plan-progress.gif)

[Видео со звуком (MP4, 14 с)](media/plan-progress.mp4)

- Одна строка на задачу: состояние, название, полоса, процент, кнопка закрытия
- Капля на полосе показывает текущий этап и шаг; при наведении — сколько времени прошло
- Этапы отмечены капсулами, шаги точками; при наведении на пройденную отметку видно, сколько она заняла, на будущую — что там начнётся
- Готовая полоса становится зелёной, показывает общее время и остаётся, пока её не закроют; с включённым `/plan-progress-autoclose` уходит сама через `doneBarSeconds` (по умолчанию 30 с, в `/config`)
- Точки заливки и строк субагентов мерцают; выключите `twinkle` в `/config`, чтобы они стояли неподвижно
- Четыре состояния: в работе, нужен ответ, ошибка, готово
- У каждого субагента своя строка под задачей: имя, модель и effort, текущий инструмент, время
- План можно менять по ходу работы; выполненные шаги сохраняются по названию
- Полосы сохраняются для каждой сессии и возвращаются при её возобновлении
- Короткие звуки при вопросе, ошибке и завершении
- Внизу видно, как быстро пишет основной диалог: `⚡ N tok/s`; субагенты не считаются
- ⚙ рядом с этой цифрой (в приложении и в полноэкранном терминале) открывает окно настроек: эффекты, автозакрытие и его секунды, звуки, сама цифра, версия мода и проверка обновлений; `/plan-progress-settings` открывает его где угодно. Окно говорит на языке из `/config`, иначе — на языке приложения или системы
- Обновления: версия в окне настроек по нажатию ищет новый выпуск, а «Обновить» ставит его и перезагружает мод на месте (если перезагрузка не сработала, попросит перезапуск). Раз в 6 часов мод проверяет и сам и, когда вышла новая версия, ставит у ⚙ метку 🔹 (в терминале — ●). Проверка — один запрос к GitHub API (`api.github.com/repos/zycck/claude-mods/releases`) без данных аккаунта и сессии; выключается переключателем «Проверять обновления» в окне или переменной `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`. Копия, установленная из папки, не проверяется
- Работает в приложении и в терминале
- В терминале полоса следует светлой или тёмной теме GNOME при теме `auto` и берёт цвета активной темы Omarchy

### Установка

Нужен Claude Code 2.1.295 или новее (`claude --version`; обновить: `claude update`). На более старых версиях часть мода не работает: окно настроек остаётся пустым, а до 2.1.286 модуль хуков не загружается вовсе, полос нет и при запуске видна строка `plan-progress: hooks module did not load`.

```
/plugin marketplace add zycck/claude-mods
/plugin install plan-progress@zycck-mods
```

Обновление:

```
claude plugin marketplace update zycck-mods
claude plugin update plan-progress@zycck-mods
```

### Команды

- `/progress` показывает или скрывает полосы
- `/progress-clear` удаляет все полосы
- `/progress-agents` сворачивает строки агентов под полосами или показывает их снова (кнопка-стрелка рядом с ✕ полосы делает это только для неё)
- `/plan-progress-autoclose` включает автозакрытие готовых полос (по умолчанию выключено) или выключает его снова; выбор сохраняется между сессиями
- `/plan-progress-settings` открывает окно настроек, как ⚙ внизу (в терминале ⚙ есть только в полноэкранном режиме)

### Как это работает

Мод регистрирует инструмент `plan_progress`. Claude один раз отправляет план, затем короткие обновления, например `{id, next: true}` или `{id, done: ["Routes"]}`. Неизвестное название шага отклоняется со списком шагов полосы. План, одобренный в plan mode, становится полосой `plan`. Строки агентов берутся из событий движка и не тратят токены.

В приложении полоса — это SVG-изображение со слоем для наведения поверх. В терминале — сетка символов, которая анимируется, только пока Claude работает.

### Тесты

`plugins/plan-progress/tests` прогоняет настоящий модуль на заглушке движка: `node compile.cjs ../hooks/register.tsx register.mjs`, затем `node regress.mjs` и `node scenarios.mjs`.
